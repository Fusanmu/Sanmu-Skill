# 采访式游戏评测

通过自适应采访，把用户真实的游戏体验整理为观点账本，必要时扫描外部评测寻找盲点，再协助写成自然、有文笔且适合发布的中文个人评测。

## 适用场景

- 游戏论坛中长评、通关评测和购买建议
- 用户有大量零散想法、口述、笔记或旧稿，但难以组织成文
- 需要区分亲身体验、客观事实、个人喜恶、作品评价和推荐结论
- 系列对比、争议作品、版本再评、DLC 或证据较复杂的深度文章

本项目把用户视为评测观点的唯一作者：不会冒充用户体验游戏，也不会把媒体或玩家社区的意见直接写成用户观点。

## 工作深度

- **快速**：适合短评或观点已经清楚的任务，只做关键追问和必要事实核验。
- **标准**：默认用于论坛中长评、通关评测和购买建议，完成自适应采访并做多源盲点扫描。
- **深度**：用于系列对比、争议作品、版本再评或证据复杂的文章，扩大相反观点和版本条件的核验范围。

## 工作流程

1. 识别已有材料和当前状态，不让用户重复已经说过的内容。
2. 确认游戏、平台、版本、进度、剧透边界、读者、篇幅和发布位置等硬约束。
3. 围绕上一轮回答追问具体例子、判断依据、覆盖范围和反例，保存有辨识度的原话。
4. 维护观点账本，区分观察、解释、作品评价、个人喜恶和推荐，并记录证据强度与适用边界。
5. 原始立场稳定后，先核验官方事实，再根据任务需要扫描专业媒体和玩家社区，整理成盲点卡交给用户筛选。
6. 在成文前确认一句话总评、主轴、支撑点、限制条件、适合人群和剧透边界。
7. 写稿后做两遍复核：先查保真，再查模板化、空总结、机械对仗和媒体化语气。

## 外部资料边界

来源优先级为官方事实、用户直接材料、专业媒体和玩家社区。外部资料用于核对事实和发现值得询问的盲点，不用于替用户补写第一人称体验。

每个候选盲点都应标明来源类型、平台／版本／难度／进度等条件，以及它与用户原始观点的关系。用户可以选择采纳、注意到但不写、与体验不符、仅作背景或待回想。

## 目录

- `SKILL.md`：技能入口、工作深度、采访流程和保真边界。
- `references/interview-and-ledger.md`：自适应采访、观点账本和声音锚点。
- `references/research-policy.md`：外部评测扫描、来源层级和盲点卡规则。
- `references/reviewer-profile.md`：评测标准与写作声音。
- `references/writing-guide.md`：从观点账本到成文的写作方法。
- `scripts/review_draft.py`：检查评测稿中的高风险句式和结构问题。
- `agents/openai.yaml`：Codex 中的显示名称、简介和默认提示词。

## 质检脚本

检查 Markdown 评测稿：

```powershell
python scripts/review_draft.py review.md
```

为脚本提供用户的声音锚点：

```powershell
python scripts/review_draft.py review.md --anchor "用户原话"
```

需要把警告作为退出失败处理时，可使用 `--strict`；需要机器可读结果时，可使用 `--format json`。脚本只能暴露风险，不能代替观点账本和人工保真回读。

## 在 Codex 中使用

调用 `$interview-game-review`，说明游戏、平台／版本、游玩进度、剧透边界以及希望得到的文章类型。若已有采访、笔记或旧稿，可直接提供，项目会从现有状态继续，不会强制重新开始采访。

完成观点整理后，如需进一步改善中文成文质量，可将确认后的材料交给 `$personal-game-review-prose`。
