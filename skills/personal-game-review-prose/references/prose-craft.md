# 游戏评测文笔方法

## 文笔从选择开始

写得好首先意味着知道什么值得展开。文章篇幅应服从用户的真实关注：最重要的体验写得更长、更具体，次要项目压缩或合并。若所有章节长度相近，通常说明作者在填模板，而不是在组织观点。

成文前为材料标记权重：

- **核心**：支撑总评，用户反复提到或有具体例子。
- **重要**：解释核心体验的代价、边界或对照。
- **补充**：有用但不改变结论，可以短写。
- **不写**：用户没注意、明确不想提、来源不稳或会破坏剧透边界。

不设固定比例。核心内容应在视觉上明显获得更多篇幅。

“补充”也不等于必须出现。记忆模糊、只有“没出问题”、又不影响总评或购买判断的音乐、性能等材料，可以直接归入“不写”。已核实事实只是允许使用，不是强制填入正文的栏目。

## 六种段落运动

“段落运动”是信息出现的方向。相邻章节尽量不要一直用同一种。完整长评有四个以上非功能性章节时，成文前先在内部给每节标注下列编号，至少使用三种，且相邻章节不重复同一种。段落数量也应服务于材料：核心内容可以四至六段，补充内容一两段即可；不要连续四节都刚好三段。

### 1. 观察 → 例子 → 判断

适合角色、关卡、美术和系统特征。先说明观察，再用用户提供的场景或机制落地，最后给出有限度的判断。

```text
角色支线很少直接解释动机。某次选择发生后，前面几段看似普通的对话才有了别的含义。用户因此认为人物塑造扎实。
```

最后一句若前文已经清楚，可以省略。

### 2. 例子 → 影响 → 判断

适合操作摩擦、资源管理和节奏问题。具体例子必须来自材料。

```text
几个区域的仓库互不相通，后期做一件东西要来回翻箱子。单次只耽误一点时间，次数多了就会持续消耗耐心。
```

### 3. 判断 → 拆解 → 保留意见

适合先表态的论坛语气。拆解时不用机械凑三点，最后允许留下边界。

```text
建造的自由度不低，辅助能力却收得很紧。……对愿意从零设计的玩家影响不大，对依赖蓝图的人会麻烦得多。
```

### 4. 预期 → 实际差异 → 评价坐标

适合系列续作或同类比较。比较的目的在解释本作，不要让前作占据主体。

```text
用户原本期待更复杂的谜题，通关后发现篇幅更多放在人物关系。谜底冲击力较弱，但人物刻画仍支撑了高评价。
```

### 5. 优点 → 代价 → 适用人群

适合购买建议或设计取舍。避免写成“不是缺点，而是取舍”；直接说明得到什么、失去什么、谁在意。

### 6. 个人背景 → 关注点 → 当前判断

适合前言。只放与评价有关的背景，不写履历表，也不在开头宣布宏大主题。

## 句子如何变好

### 用准确动词代替空泛总括

空泛：

> 时间线系统的完成度很高，体验非常出色。

更具体：

> 章节会随着推进重新排列，同一段对话也因此多出一层含义。

只有材料明确给出“同一段对话含义变化”时才能这样写；否则停在已知机制。

### 先写关系，再考虑修辞

句子之间常见的真实关系只有几类：顺承、因果、让步、条件、范围和对照。明确关系后直接写：

- 顺承：`从这里开始，收集和建造连到了一起。`
- 因果：`箱子互不相通，后期找材料会多花不少时间。`
- 让步：`谜底不算意外，人物部分仍然成立。`
- 条件：`如果主要想自由建造，这套蓝图会显得太轻。`
- 范围：`至少在主线流程里，重复感还没有盖过新鲜感。`
- 对照：`前作把力气放在结构，本作给人物留下了更多篇幅。`

最后一种是普通对照，不需要包装成“不是结构，而是人物”。

### 改写二元洞见骨架

避免：

> 它没有依靠战斗留住我，而是让我想回到这个世界。

可根据真实材料改为：

> 战斗并非重点。让我继续玩的，是收集之后还能看见这些角色在据点里活动。

若“让我继续玩”没有来源，再改为中性表达：

> 战斗占比很低，收集后的角色则会持续参与据点活动。

避免：

> 这不只是一个收集系统，更是一种陪伴。

改为：

> 收集完成后，角色仍会在据点里工作和互动。图鉴数字因此有了可见的去处。

具体信息本身往往比“更是陪伴”有力量。

二元洞见不只出现在“不是……而是……”。以下写法若先压低一端、再宣布一个整齐结论，也属于同一套路：

- `它未必有单项站到同类顶点，整体表现却很稳定。`
- `看似在写复仇，其实谈的是救赎。`
- `不一定处处惊艳，但足够完整。`
- `敌人不再只剩招式和难度。`

可以直接把两项判断分别写清，并说明范围。对照本身有信息时可以保留，不能让连接词替代分析。

### 警惕抽象的作用分配

下列句子没有明显的虚构场景，却仍可能越过材料：

- `战斗足以撑住三十小时的流程。`
- `演出方式对人物留下印象起了很大作用。`
- `剧情把整部作品的评价往上推了一截。`
- `美术负责吸引，战斗负责推进，结局负责回味。`

它们把单独成立的评价重新解释成一套心理或因果分工。用户只说“战斗正常优秀、剧情感触更深”时，应分别写清这两个判断；只有用户明确说某一项支撑自己玩下去、抬高评分或留下人物印象，才能保留相应因果。

同样不要从一个设计“有意思”自行推出“比普通调数值更容易让人记住”，也不要把“剧情感触超过战斗”扩成“剧情是给九分的重要原因”。比较对象和评分因果都需要单独来源。

### 不扩大例子的适用范围

具体例子只证明它本身。用户说某场 Boss 战可以提前削弱，只能写这场战斗的选择有意思；不能因此概括整组 Boss 都“不只靠血量和伤害制造压力”。用户说地图提示已经够用、不构成缺点，也不能替设计补上一层“保留自行寻找空间”的好处。

先把句子的主语范围与材料对齐：`这场战斗`、`这项提示`、`我这次全成就过程` 都比自动扩大成 `Boss`、`系统`、`玩家` 更可靠。缺少便利可能只是用户可以接受，不必被解释成取舍或优点。

范围控制不能泄漏成编辑说明。不要在正文里补一句 `这个例子只对应这一场战斗，没必要据此概括所有 Boss` 来证明自己谨慎。直接让句子主语停在 `这场战斗`，写完具体判断即可。`我不打算把它写成优点`、`没有需要单独提醒的问题` 也属于幕后取舍；前者改成实际态度，后者通常整段删除。

### 不把较弱感受写成后续心理

相近不等于等强。`结局很震撼`、`人物有印象` 可以原样组织，不能顺势写成 `通关后还会继续想`、`反复想起` 或 `久久回味`。回查第一人称提醒时，在内部并排写出成稿句与材料原句；如果心理动作、持续时间或因果多了一层，就降回原有谓词。

### 删除媒体稿里的安全废话

以下句子常常正确，却几乎没有信息：

- `音乐起到了应有的作用。`
- `它有成熟的类型框架。`
- `功能完整，衔接也顺。`
- `作品保留了自己的味道。`
- `这个九分我给得很干脆。`

回到具体材料：若记不住旋律但这份记忆边界本身影响评价，可以如实写；若只是“没有问题”，又不影响结论，就整节删除。能力出现得流程化就说明发生在哪里；九分依据有几项就分别写几项。不能具体化且没有功能的句子通常可以删除。

### 控制长短句

长句适合交代背景、串联条件和解释取舍；短句适合落判断、换气或制造停顿。不要连续五段都由“一句结论＋两句解释＋一句金句”组成。

检查连续段落的第一句：若都以游戏名、`本作`、`它`、`首先`或抽象判断开头，至少改变其中一部分。可以从具体机制、个人背景、时间节点、读者条件或一句承接开始。

### 允许普通句和留白

前文已经通过例子说明问题时，可以停下。不要追加：

- `这也正是它最迷人的地方。`
- `从某种意义上说……`
- `而这，或许就是……`
- `归根结底……`

章节可以结束在：

- 一个具体结果；
- 某类玩家会遇到的影响；
- 用户保留意见；
- 一句普通的个人判断；
- 通向下一节的事实。

允许总评在不同位置再次出现，只要作用改变：前言说明评价坐标，评分章节解释依据，购买推荐或结语说明适用对象。检查的是逐字重复和无信息复述，不是机械追求“同一观点只能说一次”。

## 开头的写法

前言优先交代评价坐标，不要先造“钩子”。可选择两到三项自然串联：

- 与系列或类型的关系；
- 为什么关注或购买；
- 游玩进度与时点；
- 原本期待；
- 当前总体判断。

第一节是 AI 模板最显眼的位置。禁止用 `没有……而是……`、`真正……`、虚构回忆场景或三句排比来宣布主旨。若总评暂时只能写得普通，就先普通地写清楚。

## 具体感的证据规则

具体细节只来自：用户原话、已经确认的采访材料、用户提供的稿件，或可以中性陈述的已核实事实。以下内容尤其不能凭写作需要补出：

- `我印象最深的一次……`
- 操作时身体或情绪的瞬间变化；
- 某角色对峙为何同时让用户理解双方；
- 用户继续游玩、放弃、回味或购买续作的心理原因；
- 对一段演出、音乐或美术效果的具体感受。

没有例子不等于段落不能写。可以用范围准确的概括，文笔依靠关系和节奏，不依靠伪造现场。

人物称谓同样属于事实。材料没有可靠确认代词时，重复名字或身份；不要根据立绘、名字、译名和印象补写“他／她”。用户明确给出的经验身份与强度也要原样保护，不能把“资深”润成“很熟悉”，或把“玩过很多”降成“接触过”。

## 最后一遍精修

按顺序检查：

1. 每段是否有新信息。
2. 核心内容是否明显比补充内容更充分。
3. 评价词是否能被前文具体材料支撑。
4. 相邻章节是否重复同一种运动。
5. 是否连续四节都采用相同段落数量，尤其是统一三段式。
6. 是否有连续三节都用抽象总结收尾。
7. 是否为追求文采新增了心理、因果或力度。
8. 是否把不同优点整齐分配成“撑住流程、抬高评价、留下回味”等作用。
9. 是否从一个例子扩大出了整个系统的结论，或给用户只是接受的缺点补写了设计收益。
10. 是否把“震撼／有印象”升级成“继续想／反复想／回味”。
11. 是否仍保留几处自然的个人表达和普通句。
12. 是否把范围限制、写作取舍或检查器规则泄漏成正文里的防守性说明。
13. 弱材料是否因为“栏目完整”被勉强写成一节。
14. 重申总评时，前言、评分与结语是否各自承担不同功能。

精修的目标是文章更准确、更顺、更有起伏。不要把“不像 AI”误解成故意写得粗糙。
