# 主标题与小标题方法

## 先有文章，再有标题

标题只能承诺正文已经写清的内容。正文主轴未稳定时，不要用一个漂亮比喻替它做决定。拟标题前先写下：

```text
游戏名：
文章类型：评测／简评／购买建议／再评
最具体的核心体验：
最重要的条件或代价：
用户实际给出的总评：
绝对不能暗示的主题或体验：
```

## 主标题候选池

内部至少生成九个候选，覆盖直述、具体体验和条件判断。材料中存在明确且可追溯的视觉、叙事意象或贯穿全文的概念比喻时，再生成意象／概念型候选。不要把候选池原样交给用户。

### 1. 直述型

```text
《游戏名》评测：核心体验或总体判断
《游戏名》简评：最值得讨论的内容
```

适合论坛长评和叙事作品，信息最稳。

### 2. 具体体验型

把一个确实贯穿全文的玩法、叙事或情绪结果写进标题。必须是用户已经确认的体验，不能把一段局部感受放大成全文主题。

### 3. 条件判断型

```text
《游戏名》评测：它适合怎样的玩家
《游戏名》评测：核心优点，以及需要接受的代价
```

实际标题应替换成具体内容，不使用“怎样的玩家”“优点与代价”这类占位词。

### 4. 意象／概念比喻型

```text
《游戏名》：来自本作明确材料的短意象
```

适合美术、叙事意象或核心概念确实贯穿全文，且用户愿意接受稍有文学感或讽刺意味的标题。可以省略“评测”，也不要求短语变成完整句。生成后必须回答：这个意象或比喻具体来自哪幅画面、哪种叙事元素、哪项贯穿全文的批评，或哪句用户确认材料？“一堂网络安全教育课”之所以成立，是因为文章反复讨论网络议题与推理解谜玩法之间的落差；答不出就淘汰。不要拿“余韵、回响、灵魂、旅程”一类可替换到多数游戏的词冒充意象。

## 主标题评分

每项 0～2 分，总分 12 分：

1. **准确**：没有超出用户事实、体验和评价力度。
2. **具体**：读者能知道文章重点，不只看到“诚意之作”“一次旅程”。
3. **有辨识度**：贴合这款游戏，不可轻易替换成任何作品。
4. **像本人**：论坛玩家会自然使用，不像广告、媒体专题或 AI 金句。
5. **可兑现**：正文有足够篇幅支撑标题承诺。
6. **语言自然**：直述与判断型标题去掉格式后仍是正常中文，不靠压缩词语制造“标题感”；意象／概念型标题则应是自然短语，并通过素材可追溯检查。

出现下列任一情况直接淘汰：

- 使用用户没有提出的主题、隐喻、心理变化或价值升华；
- 依赖 `不是／没有……而是……`、问句悬念或夸张承诺；
- 为对仗牺牲准确性；
- 出现 `先立住某个世界`、`难度压在长战`、`后期开始发力` 这类脱离标题便不成立的压缩搭配；
- 标题承诺无剧透正文无法论证的内容；
- 只有情绪，没有游戏名、对象或具体重点。

叙事主题型标题还要做一次“全文覆盖”检查：若正文写的是人物面对同一问题的不同选择，标题至少要呈现问题或选择之间的关系。`长生执念下的新昆仑` 只有抽象主题与地点，无法概括“拒绝、接受和主动选择死亡”，不应胜过更清楚的候选。

默认交付最高分候选。并列时优先更准确、更具体的一项，不优先更“炸”的一项。

## 小标题的任务

小标题帮助读者定位本节内容，不负责制造金句。先从正文提取“对象＋判断或影响”：

- `稍显慢热的开局`
- `建造系统的退化拉高了门槛`
- `细节中隐藏的伏笔`
- `精彩的 Meta 要素`
- `地图：具体判断`
- `战斗：具体判断`
- `缺点`
- `购买推荐`
- `结语`

这些例子展示的是具体、易懂和允许普通标题混用，不要求在新文章里复制。

## 小标题组合检查

把所有小标题单独列出来，检查：

- 只看标题能否大致知道每节写什么；
- 是否连续使用相同句式，如全部是“形容词＋的＋名词”；
- 是否为了整齐统一成相同长度或正反对仗；冒号本身不构成问题，`对象：判断` 可以连续使用，但不要让多数标题变成“初入／深入／一路／后期：判断”的阶段模板；
- 是否出现抽象词堆叠，如“回响”“底色”“温度”“重量”“答案”“灵魂”，正文却没有具体定义；
- 概念或比喻是否在正文有多个具体支点，而不是只靠标题制造文艺或讽刺效果；
- 是否存在每款游戏都能套用的口号；
- 功能标题是否被不必要地改成拗口金句。
- 去掉标题格式后，`先立住`、`压在长战`、`开始发力` 等动宾关系是否仍像正常说话；不自然就改回具体判断。

小标题组合的变化服务于识别内容，不是为了改变标点。核心章节可以写具体判断，也可以统一采用“对象：判断”；工具性章节可以直接叫“缺点”或“购买建议”。用户已指定标题格式时，以结构合同为准。

时间顺序可以体现在章节排列和正文承接里，不必让每个小标题都先写“初到／逐步／一路／后期”。用户要求标题尽量工整时，优先统一清楚程度和语气，不统一标点模板。

## 改写顺序

标题普通但准确时，按以下顺序改善：

1. 换入更具体的对象。
2. 补上本节实际影响。
3. 删除空泛形容词。
4. 调整语序和节奏。
5. 最后才考虑有限度的修辞。

完成后把直述型和判断型标题作为普通句朗读。意象／概念型标题改做素材可追溯检查。任何需要解释“标题里这样压缩才成立”的措辞，或找不到意象、比喻出处，都说明编辑尚未完成。

文笔差通常不是因为缺少比喻，而是因为标题没有说出这一节独有的内容。

## 交付候选的方式

用户只要成稿时，交付一组最佳标题，不展示生成过程。用户明确想选择时，提供三至五个方向不同的候选，例如“更直白”“更偏体验”“更强调购买条件”，每个只用一句话说明侧重。不要提供十几个同义改写让用户替编辑做筛选。
